# 이슈와 PR 작성

통합 작업 공간의 `weatherhood-specs/rules/task-management.md`와 대상 레포의 `.github/` 템플릿을 읽는다. 공유본의 위치와 실제 스킬 설치 위치는 다를 수 있으므로 작업 공간을 확인한다.

## 이슈

- 작업 대상에 따라 app, server, specs 레포를 고르고 같은 작업의 기존 이슈가 있는지 확인한다.
- 결과물의 목적에 맞는 기능·버그·설계·테스트·문서·협업 도구·유지보수 양식을 사용한다. 적합한 양식이 없으면 빈 이슈도 가능하다.
- 해당 양식의 필수 항목을 채우고 같은 이름의 라벨을 적용한다. 모르는 사실과 미정인 내용을 추측해서 확정하지 않는다. 필수 정보가 부족하면 필요한 정보를 질문한다.
- 상세 스펙은 문서로 연결하고, 작은 작업은 이슈 자체로 설명한다. 담당자·우선순위·일정·상태는 Project에서 관리한다.
- CLI로 작성할 때도 양식의 항목을 Markdown 제목으로 구성하고 라벨을 명시한다. CLI는 웹 양식을 자동 적용하지 않는다.

## PR

- 실제 diff와 수행한 검증을 확인하고 대상 레포의 PR 템플릿을 채운다. 검증하지 않았다면 이유를 기록한다.
- 작업을 연결할 때는 Refs, 완전히 완료할 때만 Closes를 사용한다. 여러 이슈와 PR의 연결을 허용한다. 다른 레포 이슈는 owner/repo#번호로 지정한다.
- 리뷰어가 변경과 검증을 이해할 수 있게 작성하고, 미정인 승인·테스트 정책을 추가하지 않는다.

작성 요청이 초안에 한정되면 게시하지 않는다. 생성·수정이 요청되면 해당 범위에서 게시하고 결과 URL을 확인한다. 여러 줄 본문은 구조화된 도구 입력 또는 임시 UTF-8 파일과 `--body-file`을 사용한다. 이슈를 Project에 연결할 수 없으면 성공했다고 보고하지 말고 남은 작업을 알린다. 이 스킬은 커밋·푸시를 자동으로 수행하지 않는다.
