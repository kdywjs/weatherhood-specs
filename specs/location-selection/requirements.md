# 지역 선택 요구사항

## 목적과 범위
현재 위치 또는 국내 지역을 선택해 날씨를 확인하고, 여러 지역을 로그인한 사용자별로 서버 DB에 저장해 다시 선택한다. 앱 진입 시 로그인이 필요하다.
이 문서는 지역 선택 기능의 기준이며 데이터 계약이나 팀 전체 MVP 확정을 의미하지 않는다.

## 지역 기준과 검색
- 선택·저장하는 지역은 국내 행정동 체계의 읍·면·동을 기준으로 한다. 법정동을 별도의 선택 지역으로 혼용하지 않는다.
- 서버가 전국 읍·면·동 목록을 미리 보관하고 검색을 제공한다. 사용자의 지역 등록은 이 목록에서 고른 지역을 개인 저장 목록에 추가하는 동작이며, 새 행정구역을 생성하는 동작이 아니다.
- 지역 이름과 상위 행정구역으로 검색할 수 있고, 결과에는 전체 지역명을 표시해 같은 이름의 지역을 구분한다.
- 검색과 현재 위치 확인은 서버의 동일한 내부 지역 ID로 지역을 식별한다. 지역명 문자열만으로 지역을 식별하지 않는다.
- 저장 지역의 날씨는 해당 지역의 대표 좌표를 기준으로 조회한다. 행정구역과 날씨 조회 격자는 별개이며, 서로 다른 지역이 같은 날씨 격자에 연결될 수 있다.
- 장소·건물 검색과 법정동·별칭 검색은 현재 확정 범위에 포함하지 않는다.

## 화면과 동작
- 메인과 날씨 정보의 지역명을 눌러 공통 지역 선택 화면을 연다. 열 때 메인 재생을 멈춘다.
- 목록에는 검색 진입, 현재 위치, 저장한 지역, 편집 진입을 둔다. 선택 지역은 체크 표시한다.
- 검색 결과는 같은 이름을 구분하도록 상위 행정구역까지 표시한다.
- 검색 결과를 누르면 저장과 지역 전환을 함께 수행하고 진입 화면으로 복귀한다. 이미 저장한 지역은 중복 추가하지 않는다.
- 다른 지역으로 전환하면 해당 지역의 현재 날짜·시각으로 이동하고 정지한다. 자동 재생하지 않는다. 날씨 정보 화면도 같은 지역을 사용한다.
- 같은 지역 재선택 또는 취소·닫기는 기존 날짜·시각을 보존하고 정지 상태로 복귀한다.
- 저장 지역의 삭제와 순서 변경은 편집 화면에서 제공한다. 현재 위치 항목은 삭제하지 않는다.
- 선택 지역을 저장 목록에서 삭제해도 현재 표시 중인 지역과 날씨는 유지한다.
- 저장 목록과 순서는 로그인한 사용자별로 서버 DB에 보관한다. 저장 지역 조회·변경은 사용자별로 구분한다.

## 현재 위치와 예외
- 현재 위치가 기본이다. 수동 선택 지역은 사용자가 바꾸기 전까지 고정한다.
- 현재 위치 모드에서는 앱이 확인한 GPS 좌표로 지역을 자동 결정한다. 사용자가 읍·면·동을 직접 고를 필요는 없다.
- 현재 위치의 지역명은 좌표가 속한 행정동을 표시하고, 날씨는 해당 행정동의 대표 좌표가 아닌 실제 GPS 좌표를 기준으로 조회한다. 따라서 같은 행정동 안에서도 좌표에 따라 조회 격자가 다를 수 있다.
- 현재 위치는 저장 지역과 별도의 고정 항목이다. 위치 확인 결과를 개인 저장 목록에 자동으로 추가하지 않는다.
- 수동 선택 상태에서는 사용자가 이동해도 선택 지역을 바꾸지 않는다. 사용자가 현재 위치 항목을 선택하면 GPS 기준 조회로 전환한다.
- 현재 위치 항목을 선택할 때 권한에 따라 위치를 확인하거나 시스템 권한 요청을 제공한다. 권한 허용만으로 수동 선택 지역을 자동 전환하지 않는다.
- 권한이 이미 거부된 경우 설정 열기와 지역 직접 찾기를 제공한다.
- 위치 확인 실패 시 기존 지역을 유지하고 재시도와 직접 검색을 제공한다.
- 날씨 갱신 실패 시 기존 캐시/실패 안내 규칙을 유지한다. 다른 지역의 캐시를 새 지역 날씨처럼 표시하지 않는다.

## 아직 정하지 않은 것
- 지역 원본 데이터의 구체적인 배포본·갱신 방식, 대표 좌표 선정과 지역 코드 매핑 검증, 행정구역 개편·폐지 시 기존 저장 지역 처리.
- 위치 재확인 시점·정확도·백그라운드 처리, 첫 실행에서 기존 지역 없이 위치 확인이 실패한 경우의 화면, 현재 위치와 수동 선택이 같은 행정동일 때의 날짜·시각 처리.
- 외부 좌표 변환 실패·행정동 결과 없음·내부 지역 코드 매칭 실패의 구체적인 오류 구분과 응답.
- 저장 개수 제한, 저장 실패 시 지역 전환 여부, 선택 모드·마지막 선택 지역의 저장 및 재실행·재설치 복원, 기기 간 동기화·동시 수정 처리. 저장 지역 최대 10개는 제안 단계이며 확정하지 않았다.
- 검색어 최소 길이·공백 처리·정렬·결과 개수·페이지 구분, 검색 지연·오류·결과 없음 처리와 법정동·별칭 검색 확장 여부.
- API 경로·요청·응답·오류 계약과 내부 DB 구조는 별도 설계한다. 와이어프레임의 지역과 수치는 가상 예시다.

## 수용 기준
1. 검색 결과 선택으로 저장과 전환이 이루어지고 중복 지역이 생기지 않는다.
2. 다른 지역 전환과 같은 지역 재선택/닫기의 날짜·시각 처리가 구분된다.
3. 위치 권한 없이 국내 지역 검색·선택이 가능하다.
4. 현재 위치 모드와 고정 지역이 구분되며 선택은 색과 체크로 함께 표시한다.
5. 목록 삭제가 현재 날씨를 임의의 다른 지역으로 바꾸지 않는다.
6. 행정동 이름 또는 상위 행정구역으로 검색하고, 전체 지역명으로 같은 이름의 지역을 구분할 수 있다.
7. 현재 위치 확인에 성공하면 해당 행정동의 내부 지역 ID와 표시 이름을 얻고, 실제 GPS 좌표 기준으로 날씨를 조회한다.
8. 검색과 현재 위치 확인 결과가 같은 행정동이면 같은 내부 지역 ID를 사용한다.
9. GPS 위치가 바뀌어도 수동 선택한 지역은 유지하며, 현재 위치 확인만으로 저장 지역이 추가되지 않는다.

## 참고 및 검증
- 근거: 지역 여러 개 저장, 지역 변경 시 현재 시각 복귀, 검색 결과 선택 시 저장·전환, 삭제·순서 변경에 대한 사용자 합의.
- 근거: 행정동 기준, 서버에 미리 적재한 지역 목록 검색, 현재 위치의 자동 결정 및 실제 좌표 기준 날씨 조회에 대한 사용자 합의.
- 관련 설계와 시안 검증: [design.md](design.md).
