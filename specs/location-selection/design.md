# 지역 선택 설계

요구사항 원본: [requirements.md](requirements.md)

결과물: [지역 선택 v1 · 5개 화면](https://www.figma.com/design/nIUPdpIqFoqtPBCBPwOJ3N?node-id=36-974)

## 화면 구성
기존 원본 Figma 파일 `nIUPdpIqFoqtPBCBPwOJ3N`에 별도 비교 프레임으로 추가한다. 메인 v3와 마이 v1의 Noto Sans KR, 흰 카드, 옅은 하늘색 배경, 청색 강조, 모서리 16px, 좌우 여백 20px을 재사용한다. 전체 화면 430×932이며 지역 선택 흐름에서는 하단 탭을 숨기고 닫기/뒤로가기로 복귀한다.

- 지역 선택: 검색창, 현재 위치 카드(지역명·현재 기온·날씨 아이콘), 저장 지역 카드, 편집 버튼. 체크는 현재 선택을 의미한다.
- 지역 검색: 뒤로가기, 검색 입력, 입력 지우기, 상위 행정구역을 포함한 결과. 키보드 영역은 시스템 UI 자리 표시이며 앱의 자체 키보드가 아니다.
- 목록 편집: 완료, 고정 현재 위치 항목, 저장 지역 삭제 및 순서 변경. 드래그 외에 위/아래 버튼을 함께 배치한다. 버튼 구성은 접근 가능한 시안 표현이며 구체적인 드래그 구현 방식은 미정이다.
- 위치 안내(요청 전): 현재 위치를 사용하는 목적, 위치 허용, 직접 검색.
- 위치 안내(거부): 설정 열기, 직접 검색. 위치 허용을 앱 설정처럼 가장하지 않는다.

## 이동과 상태
지역 선택 진입 → 검색 결과 선택(저장+전환) 또는 목록 선택 → 진입 화면 복귀. 다른 지역이면 메인 선택을 새 지역 현재 시각·정지로 바꾼다. 같은 지역/닫기이면 선택 시간은 유지한다. 편집 완료는 목록으로 복귀하며 지역을 변경하지 않는다.

현재 위치 모드와 수동 지역은 별도 선택 상태로 표현한다. 현재 위치에서 실제 지역이 변하는 경우의 재확인 정책은 미정이다. 위치 확인 결과가 없거나 실패하면 기존 지역을 유지한다.

## 산출물의 한계
정적 와이어프레임이며 검색·권한 요청·삭제·순서 변경은 실제로 동작하지 않는다. 검색 API와 저장 형식은 확정하지 않는다. 오류와 데이터 누락 상세 시안은 이번 기본 흐름 작업에 포함하지 않지만 요구사항의 예외 규칙은 유지한다.

## 검증 결과
2026-10-11 기존 파일의 (3900, 2200)에 2350×1100 비교 보드를 추가했다. 내부 화면 5개는 각 430×932이다. 플러그인으로 가져온 결과를 다시 내보내 확인한 레이어는 FRAME 54개, TEXT 64개, VECTOR 46개이며 이미지 채우기는 없다. 텍스트 서체는 Noto Sans KR로 확인했다. 전체 화면의 텍스트 잘림과 항목 겹침을 시각적으로 확인했다. 확인 이미지와 검증 메타데이터는 통합 작업 공간의 `design/figma/location-selection-v1-preview.png`, `location-selection-v1-validation.json`에 있다.
