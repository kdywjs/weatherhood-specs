# 문의하기 요구사항

## 목적과 확정 범위
사용자가 마이의 `문의하기`에서 이메일 작성으로 연결해 문의할 수 있게 한다. MVP는 별도 문의 화면 없이 OS 또는 외부 이메일 앱의 작성 기능을 이용한다.

- 진입점은 마이의 앱 정보 영역에 있는 `문의하기`다.
- 실제 수신 이메일 주소는 미정이며 임의 주소를 만들거나 실제 연락처처럼 표시하지 않는다.
- 이메일 작성 UI는 OS·외부 앱 영역이다. Weatherhood 자체 문의 화면으로 구성하지 않는다.
- 지원 서버, 앱 내 문의 폼, 접수 완료 화면은 범위 밖이다.

## 검토 제안 — 미확정
다음 세부 사항은 확정 요구사항과 구분하며 사용자 결정이 필요하다.

| 항목 | 제안 |
| --- | --- |
| 제목 | 이메일 제목을 `웨더후드 문의`로 미리 채운다. |
| 본문과 전송 | 사용자가 내용을 작성하고 이메일 앱에서 직접 전송한다. |
| 열기 실패 안내 | 수신 주소와 `복사` 버튼을 제공한다. |

## 예외와 미정 사항
- 수신 주소가 정해지지 않아 메일 연결 구현과 실제 실패 안내는 아직 확정할 수 없다.
- 주소 확정 전 문의하기를 눌렀을 때의 동작·문구, 실패 안내 형식·문구, 실패 판단 방식과 복사 결과 안내는 미정이다.
- 이메일 앱 없음, 연결 거절·오류, 작성 취소와 전송 여부를 앱에서 어디까지 확인할 수 있는지는 구현 대상 플랫폼에서 확인해야 한다. 이메일 앱을 열었다는 사실을 접수·전송 완료로 표시하지 않는다.

## 수용 기준
1. 마이의 문의하기에서 별도 Weatherhood 문의 화면 없이 이메일 작성으로 연결하는 MVP 범위가 명확하다.
2. 수신 주소를 임의 생성하지 않으며 제목·직접 전송·주소 복사는 미확정 제안으로 식별된다.
3. 지원 서버·앱 내 문의 폼·접수 완료 화면이 포함되지 않는다.
4. 주소와 예외 정책 확정 후 실제 기기에서 이메일 연결 및 실패 처리를 검증한다. 현재 문서 준비를 연결 구현 완료로 간주하지 않는다.

## 참고 및 검증
- 근거: 사용자 결정은 별도 문의 화면 없는 이메일 연결 MVP이며, 실제 수신 이메일은 미정이다. 세부 제안은 확정 요구사항과 구분한다.
