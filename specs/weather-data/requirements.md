# 지역별 날씨 데이터 요구사항

## 목적과 범위
기상청을 주 공급처로 사용해 선택 지역의 현재 날씨, 오늘의 지난 시간과 앞으로의 시간별 날씨, 날짜별 예보를 앱에 전달한다. 앱은 Weatherhood 서버에 요청하며 기상청 인증키와 공급처별 조회 방식을 알 필요가 없다.

첫 구현의 목표는 한 지역의 현재 날씨와 오늘 00시부터의 타임라인을 실제 데이터로 제공하는 것이다. 국내 지역 전체 제공과 중기예보 연결도 설계 범위에 포함하되, 실제 공급 범위를 검증하기 전 제공 일수나 시간 간격을 보장하지 않는다.

## 현재 요구사항
- 서버는 기상청 API허브를 우선 접속 경로로 사용한다. 인증키는 서버에서만 보관하고 요청 로그·응답·앱에 노출하지 않는다.
- 좌표를 기상청 격자로 변환하고 같은 격자의 데이터를 여러 요청에서 공유한다. 사용자가 선택한 위치와 공급 자료의 대표 위치를 구분한다.
- 현재 날씨와 사용자가 선택한 시각의 날씨를 구분한다. 메인의 시간 탐색이 날씨 정보 화면의 현재 요약을 변경하지 않는다.
- 오늘의 지난 시간도 탐색한다. 서버를 오후에 처음 실행하거나 처음 조회하는 지역이어도 오늘 00시부터의 자료를 확보할 수 있어야 한다.
- 해당 시각 실황을 우선 사용하고 없는 값은 해당 시각을 대상으로 한 예보로 보충한다. 보충 값은 실제 관측값으로 표시하지 않는다. 자료가 없으면 누락으로 전달한다.
- 앞으로의 가까운 시간은 초단기예보, 이후는 단기예보를 사용한다. 대상 시각·공급 항목이 겹칠 때 같은 자료 유형 안에서는 최신 발표를 사용한다.
- 단기예보 이후 날짜별 요약에는 중기예보를 사용한다. 날짜별 요약만 있는 날짜의 시간별 값을 만들어내지 않는다.
- 시간별 자료의 기온·하늘상태·강수형태·강수확률·풍속·습도와 날짜별 최고/최저를 제공 가능한 범위에서 전달한다. 제공 불가 값은 0으로 대체하지 않는다.
- 발표 시각, 대상 시각, 수집 시각과 값별 출처를 보존한다. 실황과 예보를 조합한 응답은 혼합 출처를 식별할 수 있어야 한다.
- 시간대는 `Asia/Seoul`이다. 일자 경계는 한국 현지 시각이며 API 시각에는 UTC 오프셋을 포함한다.
- 기본 단위는 ℃·m/s·mm·%다. 강수량은 집계 기간과 미만·범위·정성 표현을 보존하며, 정보 없음·강수 없음·수치 0을 구별한다.
- 앱은 조회한 타임라인으로 드래그·재생을 처리한다. 시간 눈금을 움직일 때마다 서버를 호출하지 않는다.
- 수집 자료는 최소 48시간 보존한다. 공급처의 조회 기간 제한과 서버 재시작을 고려해 저장한다.
- 날씨 정보 기능은 하단 탭 없이 별도 진입 경로로 유지한다. 아바타 꾸미기는 작은 범위로 포함하되 상세 편집 범위는 이 기능에서 정의하지 않는다.

## 예외
- 일부 항목·시간만 없으면 나머지를 제공하고 누락 목록을 전달한다.
- 갱신 실패 시 사용 가능한 이전 자료에 오래된 상태와 기준 시각을 표시한다. 오래된 자료를 허용할 최대 시간은 별도 결정 전 구현에서 임의 설정하지 않는다.
- 사용할 자료가 전혀 없으면 일시적 조회 실패를 반환한다. 다른 지역의 자료로 대체하지 않는다.
- 지원 지역 밖 좌표와 잘못된 입력을 구분한다. 국내 여부를 단순한 위경도 사각형만으로 판단하지 않는다.
- 실황의 하늘상태 누락을 강수 없음이나 맑음으로 해석하지 않는다.
- 시간 간격이 바뀌거나 자료가 빠진 구간에 이전 값을 무제한 연장하지 않는다.

## 범위 밖과 미정
첫 연동에는 대기질·자외선·일출일몰·평년 비교의 실제 공급 연결, 지역 검색, 앱 구현, 캐릭터와 배경 제작을 포함하지 않는다. 이 항목들은 제품 범위에서 제외하는 결정이 아니다.

서버 내부 기술 선택·구조·테스트 기준은 [서버 설계](../../../weatherhood-server/docs/architecture.md)를 따른다.

실제 소급 조회 방법과 범위, 실황과 예보의 제공 지연, 단기예보의 실제 지원 기간과 연장 구간, 중기예보 날짜의 메인 진입 동작, 오래된 자료 허용 최대 시간, 운영 요청 제한·재시도 수치, 최근 조회 지역의 유지 기간은 인증 검증 후 확정한다. 더위·추위·강풍 기준과 장면 우선순위는 별도 앱 공통 규칙으로 정한다.

## 수용 기준
1. 실제 한 지역을 조회해 현재 날씨와 오늘 00시부터의 시간별 자료를 반환한다. 실서버 첫 기동도 포함한다.
2. 각 값의 대상 시각·출처·발표 또는 관측 시각을 추적할 수 있다.
3. 같은 격자와 발표 자료의 동시 요청을 합치고 날짜·시각·자료 유형이 다른 자료는 구분한다.
4. 결측·일부 실패·전체 실패·오래된 자료·유효하지 않은 입력을 계약대로 구분한다.
5. 기상청 키가 응답과 로그에 노출되지 않는다.
6. 제공하지 않는 시간별 값을 일별 최고/최저나 보간으로 만들어내지 않는다.
7. 드래그·재생에서 추가 HTTP 요청 없이 선택한 시각의 수치와 장면을 함께 갱신할 수 있다.

## 참고 및 검증
- 근거: 사용자의 기상청 선택, 오늘의 지난 시간 탐색과 날씨 정보 유지 결정, 서버 수집·전달 설계에 대한 진행 요청.
- 데이터 흐름과 공급처 검증 항목은 [design.md](design.md), 앱·서버 계약은 [날씨 API](../../contracts/weather-api.md)를 따른다.
- 실제 기상청 인증 조회와 서버·앱 동작은 아직 검증하지 않았다.
