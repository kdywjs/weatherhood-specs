# 지역별 날씨 데이터 작업

담당자·우선순위·일정·진행 상태는 [Weatherhood Project](https://github.com/orgs/kdywjs/projects/1)에서 관리한다. 설계·계약은 [specs #6](https://github.com/kdywjs/weatherhood-specs/issues/6), 서버 구현은 [server #4](https://github.com/kdywjs/weatherhood-server/issues/4)에서 관리한다.

## 작업과 의존 관계
1. 요구사항·설계와 [API 계약](../../contracts/weather-api.md)을 함께 유지한다. 공급처에서 확인하지 못한 항목은 미정으로 둔다.
2. Java·Spring의 4레이어와 책임주도 설계를 적용한다. H2는 로컬 검증용이며 운영 저장소와 인증키 전달 방식을 확정한다. 키를 문서·Git·로그에 기록하지 않는다.
3. 한 지역에서 실제 실황·초단기·단기예보를 조회한다. 페이지 처리, 소급 범위, 발표 지연, 시간 간격과 단위를 확인한다.
4. 오늘 00시 자료의 초기 기동 복구 경로를 검증한다. 필요 시 API허브 시각 지정 격자 실황을 비교한다.
5. 3~4의 결과로 누락·조합·최대 오래된 시간·재시도·최근 지역 갱신의 운영 정책을 확정한다. 현재 서버의 로컬 개발 기본값을 운영 합의로 간주하지 않는다.
6. 좌표 검증·격자 변환과 기상청 조회·정규화를 구현한다.
7. 48시간 보존, 동일 자료 동시 수집 합치기, 발표 주기 갱신과 실패 시 저장본 보존을 구현한다.
8. 현재 요약·다음 24시간·일별 요약 API와 날짜별 타임라인 API를 제공한다. 중기예보는 시간별 값을 생성하지 않고 연결한다.
9. 서버 테스트 시나리오와 자동 검증을 서버 레포에 작성하고 계약 예시와 교차 확인한다.
10. 앱 연결 시 샘플 시계를 제거하고 한국 날짜 경계·드래그/재생 중 추가 요청 없음·결측 표시·현재 요약과 선택 시각 분리를 검증한다.

## 검증 항목
- 정상 한 지역, 오후 첫 기동의 오늘 00시 복구, 신규 지역 요청.
- 자정과 월·연도 경계, 날짜별 대상 시각, 구간 간격 변경과 빠진 시간.
- 실황 하늘상태 없음, 예보 보충의 값별 출처, 정보 없음/0/강수 없음/미만 값.
- 격자 경계와 서로 다른 좌표의 같은 격자 공유, 국내 밖과 잘못된 좌표.
- 여러 페이지 중 일부 실패, HTTP 200의 공급처 오류, 자료 미게시와 재시도 제한.
- 같은 키 동시 수집, 실패한 수집이 정상 저장본을 덮지 않음, 재시작 후 저장 유지.
- 오래된 자료와 일부 누락의 동시 표시, 자료가 전혀 없을 때 오류.
- 인증키와 사용자 좌표의 로그·응답 미노출.

## 후속 공급 연결
대기질·자외선·일출일몰·평년 비교는 제품 범위를 유지하며 해당 공급 경로와 정의를 확정한 뒤 별도 작업으로 연결한다. 실제 검증 증적은 [design.md](design.md) 끝에 모은다.
