# 오늘 날씨 데이터 설계

동작·예외·허용 한도의 원본은 [요구사항](requirements.md)이다. 서버 플랫폼 구조는 [서버 설계](../../../weatherhood-server/docs/architecture.md)를 참조한다.

## 흐름

행정동 확인 → 대표 좌표·공급 격자·측정소 연결 → 저장 자료 조회 → 자료별 갱신·누락 판단 → 필요한 외부 호출 → 검증 후 저장 → 24개 슬롯·최신 미세먼지 요약·하루 공통 정보 조합 순서다.

수집은 요청이 있을 때만 실행한다. 같은 공급 위치·자료 종류의 진행 중 수집을 공유하고 각 요청은 자신의 대기 상한까지만 기다린다. 독립 호출은 병렬 처리하되 초기 전역 동시 호출 상한은 공급처별 4개, 요청별 4개로 둔다. 실제 계정 호출 제한도 별도로 적용한다. 대기열 시간도 요청 수집 예산에 포함한다.

## 초기 갱신 설정

아래는 공급처 보장이 아닌 초기 운영 설정이다. 한국 시각을 사용하며 해당 시각 이후 첫 요청에서만 확인한다.

| 자료 | 확인 기준 |
| --- | --- |
| 초단기실황 | 매시 12분 이후 새 정시 자료 확인. 현재 자료는 마지막 성공 확인 후 10분 경과 시 재확인 |
| 초단기예보 | 매시 47분 이후 새 발표 확인. 발표 내 갱신은 마지막 성공 확인 후 10분 경과 시 재확인 |
| 단기예보 | 02·05·08·11·14·17·20·23시의 12분 이후 새 발표 확인 |
| 미세먼지 측정 | 매시 20분 이후 새 측정 자료 확인 |
| 일출·일몰 | 대표 좌표·한국 날짜별 최초 요청에서 수집. 두 값 확보 후 당일 재조회 없음 |

새 발표 확인 시점은 기존 성공 조회의 10분 간격보다 우선한다. 발표·대상·수집·마지막 시도·다음 재시도 시각을 구분한다. HTTP 성공이어도 기대 발표나 측정 자료가 없으면 새 자료 확보 성공으로 처리하지 않는다.

- 외부 호출 1회 제한은 2초, 사용자 요청의 총 수집 대기는 요구사항의 5초다. 남은 예산보다 긴 호출을 시작하지 않는다.
- 실패·미게시 후 같은 공급 자료는 5분 뒤의 첫 요청에서 재확인한다. 같은 요청에서 즉시 반복 재시도하지 않는다. 공급처가 더 긴 재시도 시간을 지정하면 이를 따른다.
- 공급처 장애·요청 한도 초과는 공급처 단위로 호출을 억제하고 지역별 요청으로 우회 반복하지 않는다. 인증 오류는 재설정 전 자동 반복하지 않는다.
- 상한까지 끝나지 않은 수집은 가능한 범위에서 취소한다. 이미 완료되어 검증된 결과는 저장할 수 있지만 요청 종료 후 새로운 수집을 연쇄 실행하지 않는다.
- 과거 전체를 매번 다시 조회하지 않는다. 누락된 시간, 새 실황, 새 예보와 현재 자료 갱신을 구분한다. 같은 격자에서 실황 기온·강수 형태·강수량·풍속·습도 5개 항목의 유효값을 각각 확인한다.
- 과거 슬롯에서 필요한 항목이 없으면 해당 시각에 확인 가능했던 단기예보 발표를 수집 후보로 넣고 중복 발표를 합친다. 오늘 최고·최저가 없으면 전날 23시 발표도 후보에 넣는다. 최신 자료·하루 공통 정보·과거 예보·과거 실황 순으로 후보를 배치하고 기존 5초 예산 안에서 수집한다.
- 과거 발표의 HTTP 응답이 완전하더라도 개별 결측은 남을 수 있다. 누락된 항목이 있는 과거 자료는 5분 뒤 요청에서 재확인하며, 완전한 과거 슬롯은 수집 후보에서 제외한다. 성공한 과거 요청을 영구 수집 완료로 취급하지 않는다.

## 저장과 조합

관측은 공급 위치·항목·관측 시각으로, 예보는 공급 위치·자료 종류·항목·대상 시각으로 식별한다. 집계값의 기간·단위도 보존해 서로 다른 구간을 충돌시키지 않는다. 예보는 최신 유효 발표로만 원자적으로 교체하고 늦게 도착한 이전 발표로 되돌리지 않는다. 결측은 유효값을 덮지 않으며 유지한 값의 실제 발표 시각을 보존한다.

지난 시간 보충에는 대상 시각 이전 발표만 사용한다. 이미 저장한 최신값이 이 조건을 만족하지 않으면 과거 예보를 소급 조회해 응답에 사용한다. 이전 발표를 누적 저장하지 않는 정책 때문에 재조회가 필요할 수 있으며, 확보 실패 시 null로 둔다. 오늘 과거 시각 보충은 대상 시각 기준 초단기 6시간·단기 12시간의 발표 유효성을 판단한다. 현재·미래 슬롯은 요청 시각을 기준으로 같은 한도를 적용한다. 오늘 TMN·TMX는 전날 23시 이후 발표의 최신 유효값을 오늘 하루 유지한다. 소급 가능성의 표본과 호출 비용·전국 검증 범위는 아래 참고 및 검증을 따른다.

기온·하늘 상태 등은 대상 시각을, 강수량·미세먼지는 공급 집계 구간을 기준으로 연결한다. 미래 예보의 강수량을 동일 시각의 과거 누적 관측량과 무조건 교체하지 않는다. 수치·범위 변환 근거가 없는 강수량만 null로 두고 강수 형태는 유지한다.

원본 응답은 우선 영구 저장하지 않고 검증·정규화에 사용한다. 진단 로그에는 키·정확한 GPS·원본 본문을 기록하지 않으며 공급 종류·응답 코드·소요 시간·누락 건수 등을 사용한다. DB 행 수·크기·외부 호출 수·응답 지연·부분 응답률을 확인해 보존 정책 검토 근거로 삼는다.

## 일출·일몰 연동과 저장

- `https://apis.data.go.kr/B090041/openapi/service/RiseSetInfoService/getLCRiseSetInfo`에 `locdate=YYYYMMDD`, 대표 좌표의 `longitude`·`latitude`, 십진 좌표를 뜻하는 `dnYn=Y`를 전달한다. 인증키는 서버 환경변수 `KASI_SERVICE_KEY`로만 주입한다.
- XML의 `resultCode=00`과 단일 `item`·요청 날짜 일치를 확인한다. `sunrise`·`sunset`의 공백을 제거하고 HHmm 또는 HHmmss만 허용한다. 유효 범위를 벗어난 시각은 해당 값만 누락 처리한다. 두 값이 있으면서 일출이 일몰보다 늦거나 같으면 응답을 사용하지 않는다. 외부 XML 엔티티는 비활성화한다.
- 공급 위치 키는 행정동 대표 위도·경도 문자열, 자료 종류는 `SUN`, 항목은 `SUNRISE`·`SUNSET`이다. 기존 `weather_value`에 날짜별 두 항목을 저장한다. `target`·`issued`에는 해당 한국 날짜 자정을 저장하며, 이 자료의 `issued`는 기상 예보 발표 시각이 아닌 날짜 기준값이다. 실제 수집 시각은 `collected`로 분리한다.
- 값에는 사건 시각과 응답 기준 지역명·위도·경도를 저장한다. 요청 좌표와 기준 지역 좌표를 혼동하지 않는다. API에는 사건 시각만 전달하며 내부 기준 지역 메타데이터는 노출하지 않는다.
- 당일 두 항목이 DB에 있으면 수집 후보에서 제외한다. 한 번의 완전 응답에는 다음 시도 시각을 다음 날 자정으로 기록한다. 부분 응답·실패는 기본 5분 뒤 요청에서 보충하며 정상값을 덮어 지우지 않는다. 다른 날짜·좌표의 값으로 완료 판정하지 않는다.
- KASI 호출은 기존 요청의 5초 수집 예산과 병렬 처리에 포함한다. 공급처 식별자 `kasi`를 분리해 다른 기관의 인증 실패·호출량에 영향받지 않도록 한다. 초기 호출 상한은 승인된 개발계정의 일 10,000회이며 실제 계정 조건에 맞춰 설정한다.
- 성공적으로 확보한 일출·일몰에는 기상 예보의 6·12시간 유효기간을 적용하지 않는다. 한국 날짜가 바뀌면 새 날짜의 첫 요청에서 조회한다. 별도 주기 작업·선제 수집은 없다.

## 공급 데이터와 제한

현재 연동 대상은 기상청 API허브 `VilageFcstInfoService_2.0`의 초단기실황·초단기예보·단기예보와 에어코리아 `getMsrstnAcctoRltmMesureDnsty`의 `ver=1.4` 측정자료, 한국천문연구원 출몰시각 정보의 `getLCRiseSetInfo`다. 공급처에 항목이 정의되어 있다는 사실과 모든 지역·시각에 정상값이 있다는 보장은 구분한다. 표본 조회는 아래 참고 및 검증에 기록한다.

| 데이터 | 공급 범위와 해석 |
| --- | --- |
| 기온·습도·풍속·강수 형태·강수량 | 기상청 실황과 예보를 사용한다. 강수량은 공급별 숫자·문자열·범위·집계 구간을 구분해야 한다. |
| 하늘 상태 `SKY` | 초단기·단기예보에 있고 초단기실황에는 없다. 지난 시간의 하늘 상태 보충값도 관측으로 해석하지 않는다. |
| 강수확률 `POP` | 초단기·단기예보 항목이다. 실황의 강수 여부와 구분한다. |
| 하루 최저·최고 `TMN`·`TMX` | 단기예보 항목이며 최신 발표에 오늘 값이 항상 포함되지는 않는다. 필요한 이전 발표를 확보해야 한다. |
| PM10·PM2.5 | 연결 측정소의 농도와 1시간 등급을 사용한다. 해당 행정동 자체의 관측이나 미래 시간별 예보가 아니다. |
| 통합 대기질 `khaiValue`·`khaiGrade` | 같은 에어코리아 응답에 존재한다. 현재 Weatherhood 계약에는 없으며 아래 확장 제안으로 관리한다. |
| 일출·일몰 | 한국천문연구원에 행정동 대표 좌표를 전달하며, 응답의 인근 기준 지역 시각을 사용한다. |
| 체감온도·자외선·가시거리 | 현재 호출하는 API들의 직접 제공 항목이 아니다. 필요하면 별도 연동·계산 설계를 정한다. |

강수 형태의 공급 코드와 서버 응답 값은 [API 계약](../../contracts/today-weather-api.md#강수-형태-매핑)을 참조한다. 현재 응답은 비/눈과 빗방울/눈날림을 구분하며, 화면의 표현 종류가 적다는 이유로 서버 데이터에서 구분을 없애는 정책은 합의되지 않았다.

## 매핑 검토 사항

다음 기준으로 정규화·수집을 구현하며, 공급 표본 검증과 자동 테스트는 구분한다. 구현 검증 결과의 원본은 [서버 README](../../../weatherhood-server/README.md#참고-및-검증)다.

| 항목 | 처리 기준과 남은 검토 |
| --- | --- |
| 기상청 결측 코드 | 실황·예보 강수량의 +900 이상·-900 이하 결측을 유효 강수량으로 반환하지 않는다. 잘못된 숫자·NaN·무한대·알 수 없는 범위 표현도 누락으로 처리한다. |
| 강수 없음과 값 누락 | 예보의 `강수없음`·`-`·숫자 0은 exact 0이다. 실황은 유효 수치 0만 강수 없음으로 처리한다. JSON null·필드 부재·빈 문자열·문자열 `null`은 누락을 유지하며 가이드의 null 표기를 임의 적용하지 않는다. |
| 강수량 수치·범위 | 실황 수치는 exact다. 예보의 수치 30 이상 50 미만은 [30, 50), 50 이상은 [50, ∞)로 정규화한다. 예보 수치 30 미만은 수치를 보존한다. 알려진 미만·범위·이상 문자열만 허용한다. `1mm 미만`의 공급 범주 하한 설명(0.1mm)과 현재 계약의 하한 0은 추가 검토 대상이다. |
| 강수량 기간 | 기상청 날씨누리의 1시간 예보 시간 안내에 따라 정시 대상의 직전 1시간을 사용한다. 실황 RN1도 대상 시각에 끝나는 1시간량으로 취급한다. 시간 구간을 변경하지 않으며 강수 사례의 실제 누적량 대조는 별도 검증이다. |
| 자료 종류별 코드 | 초단기 PTY 0~7, 단기 PTY 0~4를 허용하고 소나기·비/눈·빗방울/눈날림을 보존한다. 실황에 없는 SKY·POP과 공급 종류에 맞지 않는 항목은 사용하지 않는다. |
| 과거 자료와 최고최저 | 과거 슬롯은 그 시각의 유효성을 판단하며 하루 TMN·TMX는 위 저장과 조합 기준을 사용한다. 최신 발표에 값이 없을 때 필요한 이전 발표를 수집한다. |
| 검증 범위 | 서울 격자·종로구 표본을 확인했으며 눈·소나기·폭우·모든 결측 유형을 실제 수신한 것은 아니다. 공식 코드 전체의 변환 테스트와 실제 표본 검증을 구분한다. |

## 확장 및 표현 책임 제안 — 미확정

| 제안 | 근거와 결정할 사항 |
| --- | --- |
| 메인 화면의 통합 대기질 | `khaiValue`와 `khaiGrade`를 추가하면 PM 두 항목을 나열하지 않고 대기질을 요약할 수 있다. PM 상세 유지 여부, 응답 구조, 대표 측정소 선택과 누락 처리는 추가 합의 대상이다. 서로 다른 측정소의 PM 값을 합쳐 통합지수를 만들지 않는다. |
| 풍향·낙뢰·신적설 | 현재 공급 응답의 `VEC`, 초단기예보 `LGT`, 단기예보 `SNO`를 활용할 수 있다. 화면 필요에 따라 채택하며, 신적설은 강수량과 단위·의미가 다른 항목이다. |
| 기타 오염물질 | 오존 등도 같은 에어코리아 응답에 있다. 상세 화면 요구가 생기면 검토한다. |
| 서버 정규화와 앱 표현 | 추천은 서버가 공급 코드를 의미를 보존하는 공통 유형으로 변환하고, 앱이 공통 유형을 캐릭터·배경 표현으로 묶는 방식이다. 예: 공급 PTY 4 → 서버 `shower` → 앱의 비 장면. 상세 텍스트에는 소나기를 유지할 수 있다. 최종 표현 그룹과 앱의 누락 시 동작은 화면 명세에서 합의한다. |

통합대기환경지수(CAI)는 PM10·PM2.5를 포함한 6개 오염물질의 지수를 고려한 값이다. PM 두 농도의 합이나 두 1시간 등급의 최댓값으로 대체하지 않고 공급처 지수를 사용한다. PM에는 24시간 예측이동평균을 활용하므로 PM 1시간 측정값과 동일한 집계 구간을 부여하지 않는다. 종합 지수의 기준 시각·응답 형식은 채택 시 정의한다.

Apple 날씨의 한국 대기질 공급자는 BreezoMeter다. 대기질을 요약해 보여주는 방식을 참고할 수 있지만 에어코리아 지수가 Apple 표시값과 동일하다고 보장하지 않는다.

## API 계약

요청·응답 형식의 원본은 [오늘 날씨 API 계약](../../contracts/today-weather-api.md)이다. 행정동 ID 요청, 24개 슬롯, 최신 기온·미세먼지 요약과 하루 예보 최고·최저 및 일출·일몰을 제공한다. 인증 방식, 전국 공급 검증과 강수 사례의 집계량 대조는 남아 있다.

## 참고 및 검증

- 사용자가 남은 정책을 추천안대로 구체화하도록 승인한 범위의 초기 설계다. 수치는 부하 테스트나 인증 조회로 검증된 운영 결과가 아니다.
- 공급 발표 일정의 공식 근거는 [요구사항 참고](requirements.md#참고-및-검증)를 따른다.

- 2026-11-15 공급처 인증 표본 조회: 기상청 API허브의 초단기실황·초단기예보·단기예보에서 정상 응답을 확인했다. 서울 격자(nx=60, ny=127)의 당일 00시 실황, 15:30 요청의 초단기예보 6개 시간대(11개 항목, POP 포함), 전날 23시 발표 단기예보의 당일 00~23시 및 TMN·TMX를 확인했다.
