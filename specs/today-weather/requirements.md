# 오늘 날씨 데이터 요구사항

## 목적과 범위

선택한 위치의 오늘 날씨를 시간별로 제공한다. 서버가 외부 공급 자료를 수집·정규화하고 DB에 저장해 재사용하며, 클라이언트에는 하나의 오늘 날씨 응답으로 제공한다.

이 문서는 오늘 데이터 제공 요구사항의 원본이다. 공통·다른 날짜의 날씨 맥락은 [날씨 데이터](../weather-data/requirements.md)를 참조한다. API 경로·필드·오류 형식은 [날씨 API 계약](../../contracts/today-weather-api.md)에서 관리한다. 기존 계약을 이 기능에 그대로 적용한 것으로 간주하지 않는다.

화면의 최초 표시 시각, 탐색·재생·종료 동작, 캐릭터·영상·배경 선택 규칙은 범위 밖이며 화면 기능 명세에서 이 데이터를 참조한다. 주간 날씨, 지역 검색·개인 저장 지역 관리, 자산 제작도 이 기능에서 정의하지 않는다.

## 확정된 요구사항

### 날짜와 시간 범위

- 오늘은 `Asia/Seoul` 기준 날짜다. 오늘 00:00부터 다음 날 00:00 직전까지를 대상으로 한다.
- 00시부터 23시까지 1시간 간격의 24개 슬롯을 제공한다. 슬롯은 날짜·시간대·시간 키로 대상 시각을 식별할 수 있어야 한다. 화면 표시는 시간순으로 정렬하며 JSON 객체 순서에는 의존하지 않는다.
- 오늘 지난 시간도 제공 범위에 포함한다. 첫 조회 시 저장 자료가 없으면 지난 시간 자료의 소급 수집을 시도한다. 확보하지 못한 자료는 누락 규칙을 따른다.
- 시간 간격을 좁히기 위해 공급처에 없는 값을 보간하거나 복사해 만들지 않는다.
- 대상 시각과 자료의 발표·관측 시각을 구분한다. 시간별 상태값과 기간 집계값의 의미를 보존한다.

### 지원 지역

- 전국 행정동 체계의 읍·면·동을 지원 대상으로 한다. 일부 대표 도시만으로 범위를 제한하지 않는다. 실제 전국 매핑·자료 제공 검증은 별도로 수행한다.
- 수동 선택과 현재 위치 모두 같은 행정동의 대표 좌표로 날씨를 조회한다. GPS는 소속 행정동을 결정하는 데 사용하며, 같은 행정동이면 동일한 날씨 기준을 적용한다.
- 지역 식별·선택 동작은 [지역 선택 요구사항](../location-selection/requirements.md)을 따른다. 행정동과 기상청 격자는 구분하며 여러 행정동이 같은 격자 자료를 공유할 수 있다.

### 시간별 제공 항목

| 항목 | 의미와 단위 |
| --- | --- |
| 대상 시각 | 각 슬롯의 한국 현지 정시. 응답의 날짜·시간대·시간 키를 조합해 식별한다. |
| 기온 | 해당 시각의 기온, °C. 체감온도가 아니다. |
| 하늘 상태 | 맑음·구름 많음·흐림 등 하늘 상태. 강수 여부와 구분한다. |
| 강수 형태 | 없음·비·눈·비/눈 등 강수 상태. 빗방울/눈날림은 비/눈과 구분한다. 소나기·빗방울·눈날림 등 공급처 상태를 정규화하며 세부 코드 매핑은 계약에서 정한다. |
| 강수량 | 공급 자료의 집계 구간에 대한 강수량, mm. 집계 시작·종료를 식별할 수 있어야 한다. 적설 깊이와 구분한다. |
| 풍속 | 해당 자료 기준의 바람 속도, m/s. 최대 순간풍속으로 해석하지 않는다. |
| 습도 | 상대습도, %. |
| 강수확률 | 해당 예보 대상 구간의 강수확률, %. 강수량·강도나 실제 강수 여부가 아니다. |
| 미세먼지 | PM10 농도, µg/m³와 1시간 등급. 측정소 자료이며 선택 좌표의 직접 관측값으로 표시하지 않는다. |
| 초미세먼지 | PM2.5 농도, µg/m³와 1시간 등급. PM10과 별개로 제공하며 합산하지 않는다. |

- 관측과 예보를 구분한다. 지난 시각의 강수확률도 예보값이며 관측값으로 바꾸지 않는다.
- 강수량·미세먼지는 집계 구간을 갖는 값이다. 슬롯 시각이 같다고 모든 값이 동일한 순간 또는 동일 구간의 자료라고 간주하지 않는다.
- 실황과 예보를 조합할 때 항목별 출처·기준 시각을 추적할 수 있어야 한다. 외부 응답을 그대로 클라이언트에 전달하지 않는다.
- 현재 기온은 최신 실황값을 사용한다. 서버는 최신 여부·갱신 판단을 위해 발표·관측 시각을 관리하지만, 항목별 측정 시각을 화면에 표시하는 것을 필수 요구사항으로 두지 않는다. 응답 메타데이터와 화면 표시 방식은 각각 계약·화면 명세에서 정한다.
- 강수량은 정확한 수치 또는 범위로만 표현한다. 범위에는 하한·상한과 각 경계의 포함 여부를 둔다. 자유 문자열이나 임의 객체를 허용하지 않는다.
- 예를 들어 1mm 미만은 0 이상 1 미만의 범위로 표현하며, 별도 미만 유형을 두지 않는다. 임의의 중간값으로 바꾸지 않고 강수 없음과 소량 강수의 의미를 보존한다.
- 수치·범위로 변환할 근거가 없는 정성값은 강수량만 `null`로 제공하며 세부 필드는 계약에서 정의한다.

### 최신 미세먼지 요약

- 시간별 슬롯과 별도로, 선택 행정동에 연결된 측정소의 최신 PM10·PM2.5 측정 농도와 1시간 등급을 제공한다.
- 최신 요약은 현재 확인 가능한 측정 상태이며 하루 평균이나 하루 예보가 아니다. 자료 기준 시각은 서버가 관리하며, 오래된 자료는 아래 최신 요약 허용 한도를 적용한다.
- 오늘 각 시간의 측정값은 시간별 슬롯에 유지한다. 미래 또는 해당 시간 자료가 없는 슬롯은 `null`이며 최신 요약값으로 채우지 않는다.
- 요약의 일부 항목을 확보하지 못하면 해당 값은 `null`로 제공한다. 요약이 존재한다고 시간별 누락이 해소된 것으로 처리하지 않는다.

### 하루 공통 정보

- 오늘 최고 기온·최저 기온을 시간별 슬롯 밖에 제공한다.
- 오늘 일출·일몰 시각을 하루 공통 정보로 제공한다. 각각 확보하지 못하면 `null`이며 시간별 슬롯에 반복하지 않는다.
- 오늘 최고·최저 기온은 기상청 단기예보의 오늘 하루 예보값으로 제공한다. 지금까지의 관측 최고·최저는 별도 항목으로 추가하지 않는다. 24개 정시 기온의 최댓값·최솟값을 하루 최고·최저로 임의 대체하지 않는다. 전날 23시부터 현재까지 발표된 오늘 TMN·TMX 중 확보한 최신 유효값을 오늘 하루 유지한다. 최신 발표에 해당 값이 없다는 이유로 기존 값을 지우지 않는다.
- 공통 정보도 확보하지 못한 값은 `null`로 제공한다.

### 공급처와 자료 조합

- 날씨 공급처는 기상청이며 초단기실황·초단기예보·단기예보를 모두 사용한다. 접속 경로는 기존 공통 스펙의 API허브 우선 기준을 참조한다.
- 지난 시간은 실황, 가까운 미래는 초단기예보, 이후 시간과 초단기에 없는 항목은 단기예보를 활용한다. 실제 대상 시각과 제공 항목에 따라 조합하며, 세부 우선순위·보충 조건은 설계에서 확정한다.
- 미세먼지·초미세먼지는 에어코리아를 사용한다.
- 미래 미세먼지 관측값을 현재 측정값의 반복으로 채우지 않는다.
- 일출·일몰은 한국천문연구원 출몰시각 정보 API를 사용한다. 행정동 대표 좌표로 조회하며 공급처가 반환하는 인근 기준 지역의 시각이다. 실제 사용자 GPS 지점의 정밀 계산값으로 보장하지 않는다.

### 요청 기반 수집과 저장

- 요청된 위치에 필요한 자료를 수집해 DB에 저장한다. 사용자별 날씨 사본을 만들지 않고 같은 공급 격자·측정소 등의 자료를 공유한다.
- 요청 시 저장 자료의 존재·누락·갱신 필요 여부를 판단한다. 유효한 자료는 재사용하고 필요한 자료만 수집·갱신한다.
- 요청이 없는 동안 전국 또는 과거 요청 지역을 계속 주기 수집하는 방식은 채택하지 않는다.
- 갱신 필요 여부는 공급처의 발표·갱신 일정과 자료 기준 시각을 고려한다. 저장 경과 시간만으로 최신 여부를 판단하지 않는다.
- 같은 공급 자료의 동시 갱신 요청은 하나로 합쳐 중복 외부 호출을 억제한다.
- 실패·결측 응답으로 기존 정상 자료를 삭제하거나 덮어쓰지 않는다. 이전 자료는 아래 허용 한도 내에서만 반환한다.

### 일출·일몰의 일일 재사용

- 요청된 행정동 대표 좌표와 한국 날짜별로 최초 요청 때 조회하고 DB에 저장한다. 둘 다 확보하면 그날은 추가 갱신하지 않는다. 서버 재시작 뒤에도 저장값을 재사용한다.
- 다음 날짜는 그 날짜의 첫 요청에서 새로 수집한다. 전날 값을 오늘 값으로 복사하거나 요청이 없는 지역을 예약 수집하지 않는다.
- 일부 값만 확보하면 정상값을 유지하고 나머지는 `null`로 제공한다. 실패·누락은 공통 재시도 간격을 적용하며, 합쳐서 두 값이 확보되면 추가 수집을 중단한다.
- 좌표가 없거나 응답 날짜·시각이 유효하지 않으면 해당 자료를 사용하지 않는다. 일출·일몰 실패가 정상 날씨·미세먼지 응답을 막지 않는다.

### 보존과 예보 갱신

- 저장한 관측·제공용 자료는 우선 자동 삭제 없이 보존한다. 데이터 증가량을 확인한 뒤 보존·정리 정책을 재검토한다.
- 예보는 동일 공급 위치·자료 종류·항목·대상 시각에 대해 최신 유효 발표값만 유지하고 이전 발표본을 누적 보관하지 않는다. 최신 여부는 수신 순서가 아닌 발표 시각으로 판단한다.
- 초단기·단기예보와 관측값을 서로 덮어쓰지 않는다. 자료 종류별 최신값을 바탕으로 응답을 조합한다.
- 원본 응답·수집 로그의 보관 범위는 별도 설계한다. 모든 원본·로그의 영구 보관을 의미하지 않는다.

### 누락과 실패

- 일부 값만 없으면 해당 값은 `null`이며 나머지는 제공한다. 0·강수 없음과 정보 없음을 구분한다.
- 특정 시간의 모든 자료가 없으면 그 시간 슬롯은 유지하고 데이터는 `null`로 제공한다. 정확한 JSON 구조는 계약에서 정한다.
- 최초 조회는 수집한 자료가 준비되면 불필요한 지연 없이 반환한다. 일부만 확보되면 부분 응답하며 빠진 자료를 임의 생성하지 않는다. 공급처 무응답·지연에는 아래 수집 대기 상한을 적용한다.
- 공급 가능한 누락분은 다음 요청에서 보완할 수 있어야 한다. 부분 응답을 저장했다고 하루 전체 수집 완료로 처리하지 않는다.
- 공급하지 않는 값과 일시적 실패를 서버 내부에서 구분하고 불필요한 반복 수집을 방지한다. 누락 원인·갱신 실패·이전 자료 사용 여부는 클라이언트에 전달하지 않는다. 누락은 null로만 표현한다.
- 사용할 자료가 전혀 없으면 조회 불가 오류로 반환한다. 부분 성공과 전체 실패를 구분한다. 구체적인 오류 코드는 계약에서 정한다.

## 추가 확정 정책

- 강수량은 공식 변환 근거가 있는 경우에만 수치·범위로 정규화한다. 근거가 없는 정성값은 강수량만 `null`로 두고, 유효한 강수 형태는 유지한다.
- 이번 범위의 미세먼지는 최신 측정 요약과 시간별 측정값이다. 하루 단위 미세먼지 예보 등급은 추가하지 않는다.
- 행정동 대표 좌표에 가까운 운영 중 도시대기 측정소를 우선 연결한다. PM10·PM2.5를 모두 측정하는 곳을 우선하고, 없으면 항목별로 연결한다. 도로변·산업단지 등 대표성이 다른 측정망을 자동 대체로 사용하지 않는다. 연결 불가 항목은 `null`이다. 실제 연결 결과와 거리·대표성은 전국 매핑 검증에서 확인한다.
- 지난 시각은 실황을 우선하고, 없는 항목은 대상 시각 이전에 발표된 예보 중 초단기·단기 순으로 보충한다. 미래 시각은 초단기·단기 순으로 선택한다. 같은 자료 종류에서는 최신 유효 발표를 사용한다. 집계 구간이 다른 값은 같은 값처럼 대체하지 않는다.
- 현재 기온·최신 미세먼지 요약은 관측 기준 2시간 이내 자료만 허용한다. 기한을 넘기면 해당 값은 `null`이다. 오늘 지난 시간에 정확히 대응하는 관측값은 이 최신 요약 제한과 무관하게 제공한다.
- 현재·미래 슬롯의 예보는 대상 시각이 공급 예보 범위 안이고 요청 시각 기준 발표 후 초단기 6시간·단기 12시간 이내일 때만 재사용한다. 지난 시간의 보충 예보는 대상 시각 이후 발표를 제외하고 대상 시각 기준 같은 한도를 적용한다. 따라서 유효했던 과거 자료가 현재 시각 경과만으로 사라지지 않는다. 한도를 넘으면 다른 유효 공급 자료로 보충하거나 `null`로 제공한다. 이전 발표 자료 사용 여부와 유효성 판단은 서버 내부에서 관리하며 응답에 별도 상태를 추가하지 않는다.
- 현재 요청의 총 수집 대기 상한은 5초다. 필요한 수집이 먼저 끝나면 즉시 반환하고, 상한에 도달하면 확보분으로 응답한다. 기존 유효 자료도 확보분에 포함한다. 정상 값이 시간별 자료·최신 요약·하루 공통 정보 중 하나라도 있으면 부분 성공이며 전혀 없으면 조회 불가 오류다. 예보 코드의 ‘강수 없음’과 숫자 0도 정상 값이다.
- 갱신 일정과 재시도 간격은 [설계](design.md)의 초기 운영 설정을 적용한다. 수치는 성능 보장이나 공급처의 보장이 아니며 실제 검증 결과에 따라 관련 문서·계약을 함께 조정한다.

## 검증 대기 및 연계 설계

- 전국 행정동 대표 좌표와 공급 격자·측정소 연결의 실제 커버리지, 장거리 측정소 연결의 대표성을 검증한다. 검증되지 않은 전국 지원을 구현 완료로 표시하지 않는다.
- 오늘 00시부터 소급 조회, 자정 경계, 하늘 상태 보충, 공급 게시 지연·정정, 강수량 집계 구간과 미세먼지 시간 표기를 인증 조회로 검증한다.
- 최초 수집과 저장 자료 조회의 응답 시간·호출량을 따로 측정한다. 5초 상한 내 24개 슬롯의 모든 값을 확보한다고 보장하지 않는다.
- 인증 제공자·세션/토큰은 인증 기능과 연계해 정한다. 이 기능에서 임의로 인증 방식을 확정하거나 인증 구현 완료로 간주하지 않는다.
- 최종 API 필드·코드·예시와 공급 코드 매핑은 계약 작업으로 구체화하고 이 요구사항과 교차 검증한다.

### 공급 검토 후 남은 결정

[설계의 공급 검토](design.md#매핑-검토-사항)에 결측·강수량 기간·과거 예보와 최고최저 확보의 처리 기준을 기록한다. 강수량의 미확인 표현과 `1mm 미만` 범주 하한은 추가 검토 대상이며 현재 계약의 하한 0을 유지한다.

통합 대기질 추가, PM 상세 유지 여부, 풍향·낙뢰·신적설 확장과 서버·앱의 화면용 유형 통합 책임은 [미확정 제안](design.md#확장-및-표현-책임-제안--미확정)이다. 현재 제공 범위가 추가된 것으로 해석하지 않는다.

## 수용 기준

1. 부분 또는 정상 응답에는 오늘 00~23시의 시간 키 24개가 존재하며 시각이 중복되지 않는다.
2. 시간별 제공 항목·최신 미세먼지 요약·하루 공통 정보를 구분하고, 없는 값과 유효한 0을 구분한다. 최신 미세먼지 요약을 하루 평균·예보로 해석하거나 미래 슬롯에 복사하지 않는다.
3. 일부 값 누락과 시간 전체 누락은 각각 값 또는 슬롯 데이터의 `null`로 표현하며 시간 슬롯을 삭제하지 않는다. 누락 이유·부분 상태·이전 자료 사용 여부를 응답에 포함하지 않는다.
4. 기상청 세 자료와 에어코리아 자료를 조합할 수 있고, 관측·예보·집계 구간·출처를 구분한다.
5. 유효한 저장 자료는 재사용하고 요청 시 필요한 갱신·누락분만 수집한다. 동일 자료의 동시 수집을 중복 실행하지 않는다.
6. 최초 조회에서 일부만 확보되면 부분 응답하며 후속 요청에서 공급 가능한 누락분을 보완한다. 전체 자료가 없으면 오류로 구분한다.
7. 수집 실패가 정상 저장본을 훼손하지 않으며 공급처에 없는 시간별 값이나 미래 미세먼지 관측값을 생성하지 않는다.
8. 현재 위치와 수동 선택이 같은 행정동이면 동일 대표 좌표의 날씨를 제공하며 전국 읍·면·동 매핑을 검증한다.
9. 강수량의 수치·범위와 경계 포함 여부를 보존하고, 1mm 미만을 1mm 이하로 바꾸지 않는다.
10. 예보는 자료 종류별 같은 대상 시각의 최신 유효값만 유지하고 관측과 분리한다. 제공용 자료를 기간 경과만으로 자동 삭제하지 않는다.
11. 일출·일몰은 같은 좌표·날짜에 정상 수집 후 재조회하지 않고 날짜가 바뀌면 새로 조회한다. 부분 누락·실패의 재시도와 날짜 간 값 혼용 방지를 검증한다.
12. 소급 조회·공급 지연·결측·최초 요청 성능은 실제 인증 조회로 검증한다. 정책의 경계값과 부분 응답을 자동 검증한다.
