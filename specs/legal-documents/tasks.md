# 법률 문서 읽기 작업 분해

## 작업과 의존 관계
1. 실제 문서 본문과 각 시행일을 준비한다. 임의 법률 문구·연락처·날짜를 생성하지 않는다.
2. 문서 제공 방식과 로딩·실패·빈 문서 정책을 결정한다.
3. 공통 읽기 스펙과 정적 비교 보드 JSON을 검토한다.
4. root가 Figma 적용과 제목·문단 배치·잘림을 시각 검증한다.
5. 마이 스펙의 약관 하위 화면 미정 문구와 작업 항목을 연동한다. 이번 범위에서는 기존 파일을 변경하지 않는다.
6. 문서와 제공 정책 확정 후 공통 읽기 화면을 구현하고 마이 메뉴를 연결한다.

## 검증 항목
- 공통 구조와 실제 제목·절·문단·시행일 일치.
- 긴 본문 끝까지 스크롤, 상단 제목·뒤로가기 유지.
- 동의·확인 버튼 부재와 뒤로가기로 마이 복귀.
- 날씨 선택 지역·날짜·시각·재생 상태 보존.
- 확정 정책에 따른 로딩·실패·빈 문서 동작.

진행 상태·담당·일정은 GitHub Project에서 관리한다. 이번 작업은 앱·서버 구현, 커밋·푸시, Issue 수정 및 Project 갱신을 포함하지 않는다.

## 참고 및 검증
- 관련 맥락: weatherhood-specs Issue #2. 이번 작업에서 수정하지 않는다.
- 정적 JSON 검증 범위와 제한: [design.md](design.md).
- 문서 준비와 제공 정책 확정은 구현의 선행 조건이다.
