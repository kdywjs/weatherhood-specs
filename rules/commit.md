# 커밋 메시지

세 레포는 Conventional Commits 형식으로 커밋 메시지를 작성한다.

## 양식

```text
<type>(<scope>): <변경 내용>

<변경한 이유나 주요 영향>

Refs #<이슈 번호>
```

- 제목은 필수이며, 변경 내용을 한글로 간결하게 작성한다.
- `type`은 변경 종류를 나타낸다.
- `scope`는 기능이나 폴더 등 변경 영역을 짧게 적는다. 영역이 명확할 때 사용하고 여러 영역에 걸치면 생략한다. 레포가 분리되어 있으므로 `app`, `server`, `specs`를 반복해서 적을 필요는 없다.
- 본문은 선택이다. 제목만으로 설명이 부족할 때 변경 이유, 주요 영향이나 주의점을 적는다. 제목과 본문 사이에는 빈 줄을 둔다.
- 관련 이슈가 있으면 선택적으로 `Refs #번호`를 적는다. 다른 레포의 이슈는 `Refs owner/repo#번호`로 참조한다. 이슈 종료 여부는 PR에서 결정한다.

## 타입

| 타입 | 용도 |
| --- | --- |
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 변경 |
| `test` | 테스트 추가·수정 |
| `refactor` | 기능 동작을 유지하는 코드 구조 변경 |
| `style` | 공백·포맷 등 코드 의미에 영향 없는 변경 |
| `build` | 빌드 설정·의존성 변경 |
| `ci` | CI 설정 변경 |
| `perf` | 성능 개선 |
| `chore` | 위 분류에 해당하지 않는 관리 작업 |
| `revert` | 이전 커밋 되돌리기 |

## 예시

```text
fix(weather): 예보 조회 실패 시 재시도 버튼 표시

조회 실패 후 사용자가 다시 요청할 수 있도록 재시도 동작을 추가한다.

Refs #23
```

단순한 변경은 제목만 작성한다.

```text
docs(rules): 커밋 메시지 규칙 추가
```
